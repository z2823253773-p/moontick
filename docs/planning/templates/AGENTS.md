# MoonTick 共享协作规则

本文件是模板；实施时放到独立产品仓库根目录。

- 先读 `.ai/TASK_STATE.md`、`docs/planning/00_START_HERE.md` 和当前任务相关规格；不依赖聊天记忆恢复状态。
- 唯一规格来源为 `docs/planning/02_SPEC.md`。影响时间边界、计数、退出码、schema 的更改先用反例说明并记录决策。
- 默认 Claude Code 实现，Codex 独立验证；同一 checkout 只有一名写入者。active_owner 是约定，不是锁；冲突时先协调。
- 每轮只处理当前任务，修复相关问题可自主继续。新增平台、时区/容差/预测/自动修复属于范围变化。
- v0.1 为 ticks，无表头；空文件合法，空行非法，记录号=行号。不偷偷加入完整 CSV。
- core 必须 MoonBit；Python 仅独立测试。报告由实际计算产生，不手改 expected 掩盖缺陷。
- 提交前跑相关检查，候选发布跑完整 gate。记录被测 SHA、命令、结果、限制。
- 每次结束更新状态和下一步；完整证据放 `docs/evidence/`。
- 发布/对外沟通按用户已有明确授权执行；没有授权先准备具体内容。身份材料/凭据不得入库。
- 不修改父目录其他项目，不覆盖未知改动，不伪造提交、试用、CI、发布或回执。
- 角色接替时记录切换；作者不能作为唯一最终验证者。
