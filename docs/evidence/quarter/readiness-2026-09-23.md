## 剩余差距与优先级

1. **必须在截止前完成：**参赛者本人写一页 Markdown 申报书，选择新项目参与
   季度评选，提交表单、加入赛事群并保留回执。2026-09-23 尚未在本仓库获得任何
   提交或官方验收回执。表单要求申报书不要使用 AI 编写；仓库外的事实草稿不能直接
   冒充本人完成的终稿。[官网](https://moonbitlang.github.io/Hackathon2026/)
   当前列出 9 月 30 日同时为报名和验收截止；具体评选安排以官方通知为准。
2. **最值得补的证据：**请一名未参与开发者按[独立试用步骤](../../demo/independent-trial.md)
   从公开仓库运行并反馈障碍。2026-09-23 只读查询 GitHub Issues 返回空列表；
   不据此断言没有其他渠道的反馈。未经本人同意，不把私下反馈伪装成公开 Issue。
3. **下一版本的文案修复：**0.1.0 注册表归档 README 留有“尚未发布”的旧句，
   GitHub 主分支已更正。若完成反馈修复或文档改进后发布新版本，应一并更正
   包内文案，重新做包预检、独立安装与双平台 CI。0.1.0 已发布归档不因主分支
   文档更新而改变。
4. **保持如实披露：**官方 MoonBit core 归档没有可用的发行方 checksum sidecar；
   CI 记录精确 compiler 版本与观察值，但不能宣称完整供应链验证。14 条
   工具链弃用警告当前不阻断构建；若要消除，应先验证不会改变公开 API。
