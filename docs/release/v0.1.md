# MoonTick 0.1.0 发布说明

状态：**已在 Mooncakes 发布并完成独立安装复现；未报名、未验收**。本文件是技术发布说明，不是人工撰写的赛事申报书。

候选包源码/文档提交：`4a9bf78b516cf9cf166455b561a442741e896f4a`；
公开 [`v0.1.0` 标签](https://github.com/z2823253773-p/moontick/tree/v0.1.0)指向
`30ea5ec64fc5000c84b7aa526de0d3a7e1ea97cd`。模块：
`z2823253773-p/moontick`；许可证：MIT；仓库：
<https://github.com/z2823253773-p/moontick>；[Mooncakes 0.1.0 版本页](https://mooncakes.io/docs/z2823253773-p/moontick@0.1.0)。

v0.1.0 核心由用户声明整数毫秒窗口 `[start,end)` 与固定步长，核算网格覆盖、
压缩缺失区间，以及重复、乱序、离网格和越界记录。提供 MoonBit core 库、严格
单列 ticks 输入适配层、文本/JSON 报告和 native CLI。缺席整段窗口也会失败；
重复行不能填补缺口。三组[合成示例](../../examples/README.md)分别演示归档、
聚合桶与重复加缺失，每组都有成功和失败输入。

已核实的质量证据：固定编译器 `moonc v0.10.14+7d59c7ec9`；
[macOS arm64 与 Linux x86_64 的候选 CI](https://github.com/z2823253773-p/moontick/actions/runs/35748833083)
在只多出内部证据文档的 SHA `aebf418` 下各完成 77/77 MoonBit 测试、42/42 进程级
CLI 测试及独立差分 oracle。候选元数据/示例变更后本机也重复运行相同门槛，六个示例与
隔离解压归档的 native check/build 也通过。29 文件发布归档的清单、哈希和边界在
[`docs/evidence/T6/release-preflight.md`](../evidence/T6/release-preflight.md)。

已知限制：仅支持一个有限、固定步长的整数毫秒计划；不直接解析 CSV，不推断时区，
不容忍时间抖动、不处理可变日历步长，也不补值或修复数据。输入上限为 32 MiB、
250000 行、单 token 20 字节。官方 core 归档没有可用的发行方校验文件；
`moon publish --dry-run --frozen` 的服务端曾接受预检但 CLI 返回 255，原因尚未证实；
正式 `moon publish --frozen` 随后退出 0、服务端返回 200，仓库外工程安装并通过
2/2 API 用例。详见[发布与消费者核验](../evidence/T6/release-and-consumer.md)。
Mooncakes 已上传的 0.1.0 README 留有发布前“尚未发布”的旧句；GitHub 主分支已更正。
这不影响包内容或 API，但若要更新注册表中的 README，应按后续版本发布，不能把
GitHub 文案修正冒充已上传归档变更。
